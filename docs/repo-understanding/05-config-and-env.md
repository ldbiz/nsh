# Configuration and environment

## Primary configuration
`src/config.rs` defines the typed configuration, default values and settings validation/loading. The user-facing entry points are `nsh config` and `nsh autoconfigure`; see `src/app/config_command.rs` and `src/autoconfigure/`.

| Configuration group | Purpose | Consequence |
|---|---|---|
| `provider`, `provider_routing`, `models` | LLM connection, model selection and routing | Determines remote provider calls |
| `context`, `capture` | How much terminal/project context is collected | Changes information available to queries |
| `execution` | Prefill, confirmation, autorun and intermediate execution | Changes the approval boundary |
| `tools`, `mcp`, `web_search` | Agent capabilities and external integrations | Controls possible tool calls |
| `redaction` | Secret filtering | Affects data sent to providers |
| `memory` | Persistence, retrieval and maintenance | Changes retained context |
| `db` | Database handling | Affects persistence behaviour |
| `shell_hooks`, `hints` | Hook behaviour and failure hints | Changes interactive UX |
| `remote` | Remote connectivity | Enables/disables remote functionality |
| `display`, `debug` | Presentation and diagnostics | Changes local output/logging |

## Runtime environment
| Variable or location | Role |
|---|---|
| `NSH_SESSION_ID` | Identifies the active shell session |
| `NSH_TTY` | Terminal identity used by hooks and session operations |
| `NSH_NO_WRAP` | Shell-side control for wrapper behaviour |
| `NSH_HOOK_HASH` | Tracks loaded shell integration version |
| `HOME` / `~/.nsh/` | User state, managed binaries, config and local artefacts |
| `~/.nsh/bin/nsh-core` | Managed core binary resolved by the shim |

Provider credentials and remote pairing keys are sensitive configuration. Do not copy them into diagnostics or documentation.

## Defaults and examples
The README documents `?` for normal queries, `??` for thinking, `?!` for private mode and `!!` for forced auto-execution. It also describes prefill as the normal command delivery mode, with confirmation and autorun alternatives.

The default Cargo feature set includes `remote`. For precise default values and precedence, consult `Default` implementations and loading methods in `src/config.rs` rather than relying on examples.

Development and tests use isolated home directories in integration tests. Shell-specific initialization is generated by `nsh init <shell>`.

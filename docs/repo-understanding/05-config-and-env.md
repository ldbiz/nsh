# Configuration and environment

## Primary configuration
`src/config.rs` defines the typed configuration, default values and settings validation/loading. The user-facing entry points are `nsh config` and `nsh autoconfigure`; see `src/app/config_command.rs` and `src/autoconfigure/`.

| Configuration group | Purpose | Consequence |
|---|---|---|
| `provider`, `provider_routing`, `models` | LLM connection, model selection and routing | Determines remote provider calls |
| `context`, `capture` | How much terminal/project context is collected | Changes information available to queries |
| `execution` | Prefill, confirmation, autorun and intermediate execution | Changes the approval boundary |
| `tools`, `mcp`, `web_search` | Agent capabilities and external integrations | Controls possible tool calls |
| `redaction` | Secret filtering | Affects data sent to providers |
| `memory` | Persistence, retrieval and maintenance | Changes retained context |
| `db` | Database handling | Affects persistence behaviour |
| `shell_hooks`, `hints` | Hook behaviour and failure hints | Changes interactive UX |
| `remote` | Remote connectivity | Enables/disables remote functionality |
| `display`, `debug` | Presentation and diagnostics | Changes local output/logging |

## Runtime environment
| Variable or location | Role |
|---|---|
| `NSH_SESSION_ID` | Identifies the active shell session |
| `NSH_TTY` | Terminal identity used by hooks and session operations |
| `NSH_NO_WRAP` | Shell-side control for wrapper behaviour |
| `NSH_HOOK_HASH` | Tracks loaded shell integration version |
| `HOME` / `~/.nsh/` | User state, managed binaries, config and local artefacts |
| `~/.nsh/bin/nsh-core` | Managed core binary resolved by the shim |

Provider credentials and remote pairing keys are sensitive configuration. Do not copy them into diagnostics or documentation.

## Defaults and examples
The README documents `?` for normal queries, `??` for thinking, `?!` for private mode and `!!` for forced auto-execution. It also describes prefill as the normal command delivery mode, with confirmation and autorun alternatives.

The default Cargo feature set includes `remote`. For precise default values and precedence, consult `Default` implementations and loading methods in `src/config.rs` rather than relying on examples.

Development and tests use isolated home directories in integration tests. Shell-specific initialization is generated by `nsh init <shell>`.


## Configuration files, precedence and representative defaults

- **Global user file:** `~/.nsh/config.toml` on Unix. On native Windows, `Config::path()` resolves within the user's local application-data directory.
- **Project override:** `.nsh.toml` or `.nsh/config.toml`, found by walking from the current directory towards the Git root. The loader deep-merges permitted overrides with the global configuration, but **only `[context]` and `[display]` are accepted** from project files. Provider, execution, tool, redaction, memory and remote settings cannot be overridden there.
- **Missing or invalid configuration:** Defaults in `src/config.rs` are used if the file is absent or its TOML cannot be parsed (with a warning for parse errors).

| Setting | Code default | Meaning |
|---|---|---|
| `execution.mode` | `prefill` | Suggest editable commands rather than automatically running final suggestions |
| `execution.max_tool_iterations` | `50` (clamped to 1–200) | Limit a query's tool loop |
| `execution.confirm_intermediate_steps` | `false` | Allow safe pending intermediate steps to run without a per-step approval prompt |
| `execution.allow_unsafe_autorun` | `false` | Guard elevated-command autorun; dangerous commands still require explicit confirmation |
| `context.scrollback_lines` | `1000` | Recent PTY output retained |
| `context.include_other_tty` | `true` | Permit other-session summaries to enter context |
| `capture.mode` / `capture.alt_screen` | `vt100` / `drop` | Output interpretation and alternate-screen handling |
| `redaction.enabled` | `true` | Filter matching secrets from model-bound text |
| `memory.enabled` / `memory.inject_prompt` | `true` / `true` | Store and retrieve long-term context |
| `memory.incognito` | `false` | Pause persistent memory activity when enabled |
| `remote.enabled` | `false` | Start the optional iroh endpoint only when enabled |

## Session/wrapper and credential variables

| Environment variable | Role |
|---|---|
| `NSH_SESSION_ID`, `NSH_TTY` | Associate commands, prompts and history with a shell session and its terminal |
| `NSH_WRAP_SESSION_ID`, `NSH_ORIG_TTY` | Carry session and original TTY identity across shell re-exec |
| `NSH_PTY_ACTIVE`, `NSH_NO_WRAP` | Avoid nested wrapping or deliberately skip it |
| `NSH_WRAP_SCROLLBACK_LINES`, `NSH_WRAP_CAPTURE_MODE`, `NSH_WRAP_ALT_SCREEN_MODE` | Configure the long-lived PTY capture process |
| `NSH_WRAP_MAX_OUTPUT_STORAGE_BYTES`, `NSH_WRAP_SCROLLBACK_RATE_LIMIT_BPS`, `NSH_WRAP_SCROLLBACK_PAUSE_SECONDS` | Bound capture size and throughput |
| `NSH_HOOK_HASH`, `NSH_HOOKS_VERSION` | Track and refresh shell hook versions |

Provider credentials can be supplied via `[provider.<name>].api_key`, by a local `api_key_cmd`, or by provider-specific environment variables such as `OPENROUTER_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY` and `DEEPSEEK_API_KEY`. An API key is required for most hosted providers; a configured local provider (for example, Ollama) can avoid this. Never commit key values.
